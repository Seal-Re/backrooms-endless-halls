# 设计规格：《后室·无尽回廊》文字生存游戏

> 类型：单文件离线网页文字游戏 / 互动小说（IF）
> 编写日期：2026-06-13
> 上游调研：见 `游戏/调研-现有游戏与引擎.md`
> 世界圣经：仓库 `后室/` 知识库（层级 / 实体 / 物品 / 组织 共 ~120 文件）

---

## 0. 已锁定决策（来自需求澄清）

| 维度 | 决策 |
|---|---|
| 技术栈 | **纯手写单文件 HTML + JS 引擎**（AI 作者最可控、可测；分文件开发 → build 内联成单 HTML） |
| 玩法 | **分支选项 + 状态栏 + 物品生存**（hybrid，非纯 CYOA、非 parser） |
| 规模 | **大型**：10-12 层 + 组织线 + 多起点 + 8+ 结局 |
| 叙事驱动 | **全脚本离线**（确定性，不依赖 LLM/联网） |

---

## 1. 目标与成功标准

**目标**：在 Windows 本机交付一款双击 `后室-无尽回廊.html` 即可游玩的后室题材文字生存游戏，含状态/物品/分支/多结局，氛围以"存在性孤独"为核心。

**成功标准（验收）**：
1. 单文件 `后室-无尽回廊.html` 零依赖、离线、双击运行（file:// 下正常）。
2. 至少 10 个可达层级、8 个可达结局；`lint.mjs` 通过（无悬空 goto / 不可达结局 / 非法物品引用 / 死选项）。
3. `test.mjs` 随机漫游 ≥1000 局无未捕获崩溃、无非法死胡同（卡死无任何可选项且非结局）。
4. 核心循环（Sanity 隐藏 + 杏仁水多变体 + 实体规避）可玩可感知；理智低段触发不可靠叙事。
5. 存档：安全屋自动存档 + 手动槽位 + 存档串导出/导入（单文件可移植）。
6. 中文 UTF-8 正常；CRT 终端观感（黑底琥珀字 + 状态栏）。

**非目标（YAGNI）**：多人、实时反应、parser 指令、LLM 生成、音频/美术大资源、移动端适配。

## 2. 架构

```
游戏/
  src/
    engine.js              # 状态机 / 效果原语 / 渲染 / 存档 / 种子化 RNG
    style.css              # CRT 琥珀终端风
    index.template.html    # 壳：状态栏 + 正文区 + 选项区 + 存档区，占位符注入
    data/
      items.js             # 物品表（杏仁水四变体 + 火盐/镜子/手电…）
      entities.js          # 实体表 + 每层规避规则
      orgs.js              # 组织（MEG / UEC / The Lost）NPC 与阵营
      endings.js           # 结局定义 + 触发条件
      start.js             # 多起点开局
      levels/
        L0.js L1.js L2.js L3.js L5.js L6.js LFun.js LExcl.js LInf.js TheEnd.js …
    build.mjs              # 内联 src → 单 HTML（资源 base64）
    lint.mjs              # 静态内容校验器
    test.mjs              # 随机漫游自动测试
  后室-无尽回廊.html        # ★交付物（build 产出）
  调研-现有游戏与引擎.md
  设计-后室无尽回廊.md      # 本文件
```

**原则**：内容（data/）与逻辑（engine）分离；状态转移为纯函数；data 为声明式对象，便于并行编写与机器校验。最终 build 把所有 css/js/data 内联进单一 HTML（无外链，保双击离线）。

## 3. 引擎数据模型

### 3.1 运行时状态（GameState）
```js
{
  level: "L0",          // 当前层级 id
  node:  "entry",       // 当前节点 id
  sanity: 100,          // 0-100，隐藏
  thirst: 0,            // 0-100，越高越渴
  stamina: 100,         // 0-100
  turns: 0,             // 回合计数（驱动经济与冷却）
  inv: { almond_grey: 2, flashlight: 1, battery: 3 }, // 物品→数量
  flags: {},            // 剧情旗标（延迟后果 / 结局判定）
  trust: 0,             // 同伴信任（替代多人 panic）
  visited: {},          // "level:node" → 次数（循环/漂移判定）
  seed: 0,              // 种子化 RNG（可复现），new game 时生成并存档
  redCooldown: 0,       // 杏仁水·红 冷却到的 turn
}
```

### 3.2 内容模型
```js
level = {
  id, name, class /*0-5*/, danger, entities: ["hound", ...],
  safe: bool,                 // 是否安全屋（存档点 + SAN 回升）
  nodes: { [id]: node }
}

node = {
  id,
  text,                        // 字符串或 (state)=>string，可插值；支持 sanity 变体
  variants: { lowSanity: ... },// 可选：低理智不可靠叙事覆盖
  onEnter,                     // 可选 (state)=>effects[]：进入即生效（扣 SAN / 触发遭遇）
  random,                      // 可选：加权随机事件表（roguelike 节点）
  choices: [ choice ]
}

choice = {
  label,                       // 选项文案
  requires,                    // 可选 (state)=>bool：不满足则隐藏或灰显
  effects,                     // (state)=>void | 效果原语数组：改数值/增删物品/置flag
  goto,                        // "node" 或 "level:node"
  ending                       // 可选：结局 id（终局选项）
}
```

### 3.3 效果原语（声明式，便于校验与测试）
`sanity±N` `thirst±N` `stamina±N` `give(item,n)` `take(item,n)` `flag(name,val)` `trust±N` `goto(target)` `dropLevel()`(no-clip 随机跌层) `end(endingId)`

## 4. 核心系统

### 4.1 Sanity（理智，隐藏）
- 每回合自然 -1~-3；黑暗 / 独处 / 目击错位事件额外扣；安全屋 / 杏仁水回升。
- **不显示数字**：用感官反馈分级表达——
  - 70-100：正常。
  - 40-69：幻听（嗡鸣变调、墙后抓挠、含糊低语）。
  - 15-39：假实体、文字偶发重复/错字、"熟悉的人声"喊你名字。
  - 0-14：不可靠叙事（节点 `variants.lowSanity` 接管，选项可能撒谎），逼近"理智归零"结局。
- 设计准则：感官反馈而非数字；系统互咬（黑暗→SAN↓，光源是消耗品）。

### 4.2 杏仁水多变体（对接 `后室/物品/01-杏仁水`）
| 物品 id | 名称 | 效果 | 限制/副作用 |
|---|---|---|---|
| `almond_grey` | 杏仁水·灰 | thirst-50, stamina+30, sanity+15 | 基本无 |
| `almond_green` | 杏仁水·绿 | stamina+50, 临时加速 | 成瘾 flag，之后每回合额外 sanity-1 |
| `almond_red` | 杏仁水·红 | 治病 / 驱退剥皮者 | **8h（≈若干 turn）冷却**；过量致癌 flag |
| `almond_blue` | 杏仁水·蓝 | sanity+30，抗心灵影响 | 稀有 |

其它：`firesalt`(驱实体) `mirror`(检测拟态/剥皮者) `liquid_pain`(交易) `flashlight`+`battery`(照明，电量消耗，与 SAN 咬合)。**忌无限补给**——稀缺即恐惧。

### 4.3 实体规避（对接 `后室/实体/`）
- 每层不同实体 + 不同规则；遭遇 = 限回合 / 限时选择；错套规则 → 死亡结局。
- 例：L0 Hound（远离声源）/ L1 Smiler（不可直视黑暗中的笑）·剥皮者（用镜子/红水验明同伴）/ LFun 派对客（不可加入狂欢）/ Deathmoth（避光源招引）。
- **不描述实体本体**——只写痕迹、声音、错位（文字媒介优势）。

### 4.4 no-clip 跌层
- 种子化 RNG（`seed`，可复现，呼应 roguelike 静态层+随机节点）。
- 小概率 `dropLevel()` 把玩家甩到非预期层级，既机制又叙事张力。

## 5. 叙事结构

**主干 = Branch-and-Bottleneck + Quest 混合**：
- 每层级 = 一个 bottleneck 出口汇合点。
- 层内 = 若干 quest 节点（地理探索）+ 随机事件节点。
- 危险层（Level !）用 **Gauntlet**（线性高致死走廊 + 死亡剪枝）。
- 迷路层（红房间 / 边缘移位）用 **Loop**（循环 + 微小漂移，靠 `visited` 计数推进）。

**多起点（3 个开局）**：
1. 仓库夜班 → no-clip → L0（标准开局）。
2. 校园走廊深夜 → L0 变体（不同开场文案 + 初始物品差异）。
3. 酒店电梯 → 直坠 L5 恐怖旅馆（高难开局）。
三起点汇入共享层级网络。

**组织线（对接 `后室/组织/`）**：
- **MEG**：援助 / 招募，可获补给与情报；trust 高 → MEG 结局。
- **UEC**：无垠探索者，硬核探索路线。
- **The Lost**：危险邪教，诱骗玩家，错信 → 坏结局。
- 中段 NPC 遭遇用 `flags`/`trust` 记录，影响结局走向。

## 6. 层级与结局

### 6.1 层级清单（首版 10-12）
L0 阈界 / L1 宜居地带 / L2 废弃公共带 / L3 发电站 / L5 恐怖旅馆 / L6 熄灯 / Level Fun 欢乐层级 / Level ! 不想死就快跑 / Level ∞ 无限层级 / The End 终焉（真结局门）。
（可视进度增补 Level 9 郊区等。）

### 6.2 结局清单（8+，由 `flags` + 关键状态共同判定）
1. **逃回前厅**（真结局，需集齐条件：到达 The End + 关键道具 + 同伴/组织条件）。
2. **困死 L0**（资源耗尽，对应"85% 走不出 L0"设定）。
3. **理智归零 → 成为后室一部分**（不可靠叙事终点）。
4. **被剥皮者取代**（未用镜子/红水验明同伴）。
5. **被 Smiler 吞噬**（直视黑暗中的笑）。
6. **加入 MEG**（trust 达标的安定结局）。
7. **永坠红房间循环**（Loop 层迷失）。
8. **抵达 The End**（隐世结局，区别于真结局逃出）。
（The Lost 邪教坏结局、UEC 深潜结局可作扩展。）

## 7. 文风与观感

**文风规范**：第二人称现在时贯穿；先平庸后错位（先写日常细节再插不可能元素）；感官极简（荧光灯嗡鸣 / 白噪 / 寂静 > 视觉奇观）；**严控 jumpscare**（1998 教训）；循环描写埋微小漂移；理智低段写不可靠叙事变体。

**观感（CRT 终端皮）**：黑底、琥珀/病黄等宽字（monospace）、轻微 CRT 闪烁/扫描线（CSS，可关）、顶部状态栏（当前层级 · 口渴粗粒度标签 · 杯子数 · 背包入口）、正文区、选项区、底部存档区。无障碍：可关闭闪烁、字号可调。

## 8. 构建与测试

### 8.1 构建
- 优先 **Node**：`node src/build.mjs` 读取 engine/style/template/data，内联成单 `后室-无尽回廊.html`（资源 base64）。
- **先验本机 node**；若无 → PowerShell 内联回退脚本（字符串拼接 + 占位符替换）。

### 8.2 测试（治"手写易乱"，配合 TDD）
- `lint.mjs`：静态校验——所有 `goto`/`level:node` 目标存在；所有结局可达（图可达性）；物品引用合法；无"无可选项且非结局"的死节点；无"不同选项同结局同效果"的无意义选项。
- `test.mjs`：种子化随机漫游自动跑 ≥1000 局，捕获崩溃 / 死胡同 / 非法状态。
- 引擎纯函数（效果原语、sanity 分级、RNG）写单元测试。
- 先跑通 **L0 → L1 最小闭环 + 1 死亡 + 1 推进结局** 验证手感，再铺量。

---

## 9. 开发顺序（落地编排）

1. 脚手架：engine.js（状态/效果原语/渲染/存档/RNG）+ style.css + template + lint/test 骨架。
2. 最小闭环：L0 → L1 一条主线 + 1 死亡结局 + 1 推进结局；验证 SAN 隐藏反馈 + 杏仁水经济手感。
3. 接世界圣经：把 `后室/层级·实体·物品·组织` 转写为 data；lore 自洽防漂移。
4. 并行铺量（Workflow）：每层级一个 agent 写 `data/levels/*.js`，统一节点契约。
5. 整合：build + lint + test 全绿；补多起点 + 组织线 + 8 结局。
6. 氛围打磨 + 导出验收：单 HTML 双击验证可玩 / 存档 / 多结局可达。
